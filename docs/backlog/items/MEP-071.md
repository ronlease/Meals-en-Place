## [MEP-071] Chore: Fix TypeScript Member Ordering Violations and Raise the Rule to Error

**Status:** Backlog
**Priority:** Low

### Business Problem
The alphabetical member ordering rule for TypeScript is enforced by `@typescript-eslint/member-ordering` in `src/MealsEnPlace.Web/eslint.config.js`. It is set to `warn` because 71 existing violations across 38 files predate it. Until they are fixed the rule cannot fail CI. The rule was dropped for C# (no stock analyzer; the cost of a custom one was not worth it), so this item covers TypeScript only.

### Acceptance Criteria
```gherkin
Feature: TypeScript member ordering enforcement
  Scenario: Existing code conforms
    Given the rule is set to warn and reports 71 violations
    When the members of each affected class are reordered alphabetically
    Then `npx ng lint` reports 0 member-ordering problems
    And all Web tests still pass

  Scenario: The rule fails the build
    Given `npx ng lint` reports 0 member-ordering problems
    When the rule severity is raised from warn to error
    Then a class with out-of-order members fails `npx ng lint` and the CI lint job

  Scenario: No behavior change
    Given members are reordered only
    Then no member is renamed, added or removed
```
